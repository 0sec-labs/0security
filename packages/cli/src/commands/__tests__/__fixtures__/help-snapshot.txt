### 0security
Usage: 0security [options] [command]

A security agent for your code: scan, fix, SBOM and evidence. Run 0security to open the console.

Options:
  -h, --help                       display help for command
  -p, --print <prompt>             Run one prompt headless: only the answer goes to stdout
  -c, --continue                   With -p: continue the most recent thread
  -r, --resume <id>                With -p: continue a saved thread

Work:
  scan [options] [target]          Scan a folder or git repository for security bugs; prints the
                                   findings as a report
  threat-model [options] [folder]  Draft the repository's threat model as a file for people to
                                   review (optionally as a pull request)
  probe [options] <url>            Send adversarial messages to a live model or agent endpoint and
                                   report the ones it obeys
  redteam                          Test whether an agent obeys poisoned text: a fake MCP server that
                                   records its calls, and a judge that reads the recording
  eval                             Evaluate tool-using agents with suites of paired security and
                                   utility cases on the redteam honeypot
  sbom                             Generate an SBOM from lockfiles, check one against known
                                   advisories, and scan model files and agent configuration
  findings [options]               Browse findings and change their status
  evidence                         Check that an evidence folder was signed with your key and is
                                   unchanged
  threads                          Start, follow and stop threads
  sentinels                        Create, run and change Sentinels

Setup:
  skills                           Skills and extensions: list, add
  models                           Models and provider connections
  computers                        Remote computers that run 0
  config                           Settings, API keys, team and setup checks (config doctor)

Run `0security <command>` to list its subcommands; `0security <command> <subcommand> --help` for flags.

Examples:
  0security -p "Review ./app for injection bugs"
  0security threads start "Map the login flow" --wait
  0security findings list --severity high --format json
  0security sentinels list --presets

### 0security eval run
Usage: 0security eval run [options] <suite>

Run a suite and report security pass rate, utility pass rate, secure-and-useful and inconclusive
rate per agent; exits 1 if the verdict fails, 2 if no run was conclusive

Arguments:
  suite                   Suite file (JSON or YAML)

Options:
  --agent <id>            Only run this suite agent (repeatable)
  --repeats <n>           Override the suite's runs per agent and case (1 to 20)
  --max-runs <n>          Stop after this many runs; a cut-short run fails the verdict
  --timeout <seconds>     Stop an agent run after this long (1 to 3600) (default: 120)
  --format <format>       text, json, md or sarif (default: "text")
  -o, --output <file>     Write the result (in --format) to this file instead of stdout, even when
                          the exit code is 1 or 2
  --baseline <file>       Compare with a baseline saved earlier; any regression fails the verdict
  --save-baseline <file>  Save this run's pass rates as a baseline (rates and counts only)
  --tolerance <fraction>  Drop in a pass rate to ignore when comparing with the baseline (0 to 1)
  --unsafe-no-isolation   Required: there is no sandbox yet, so each agent runs on this machine with
                          the access you give it. POSIX only
  -h, --help              display help for command

### 0security findings
Usage: 0security findings [options] [command]

Browse findings and change their status

Options:
  --db-path <path>                  Path to SQLite database
  --scan <scanId>                   Filter by scan ID
  --severity <severity>             Filter by severity: critical, high, medium, low, info
  --category <category>             Filter by attack category
  --status <status>                 Filter by status: discovered, verified, confirmed, scored,
                                    reported, fixed, false-positive
  --triage <triage>                 Filter by triage: new, accepted, suppressed
  --expiring <days>                 Only accepted risks that expire within this many days
  --context <file>                  Business context file (JSON): order findings by what matters to
                                    you, with the reason shown. Defaults to the file set with
                                    `0security config set findingsContext`
  --repository <name>               Repository name the context rules are matched against (default:
                                    the git remote of the current folder)
  --scope <scope>                   in: findings not labelled out of scope; out: only those the
                                    declared scope (0security scan --scope) labelled out of scope;
                                    all (default): both, each labelled
  --limit <n>                       Max findings/groups to show (default: "50")
  --all                             Show raw finding rows instead of grouped fingerprints (default:
                                    false)
  -h, --help                        display help for command

Commands:
  list [options]                    List findings from the database
  show [options] <id>               Show detailed information about a finding
  update [options] <id>             Change a finding's status
  import [options] [file]           Import findings from another scanner's SARIF 2.1.0 file (CodeQL,
                                    Semgrep, ZAP, Strix, Nuclei and others) or Nuclei JSON Lines
                                    (use - for stdin), or from GitHub security alerts. Nothing in
                                    the file is executed.
  fix [options] <finding>           Fix one finding in an isolated git work tree and open a pull
                                    request for review
  burndown [options]                Work through open findings in batches: one fix branch and pull
                                    request each, then a report
  verify [options] [finding...]     Experimental: re-check findings with a fresh thread each and
                                    record a verdict next to them
  metrics [options]                 Show what scan, fix and verify runs cost and produced: cost per
                                    proposed fix and the share that passed their checks
  rollup [options] [inputs...]      Count open findings across repositories by severity, category,
                                    age, owner, team and tier, from export files, SARIF files and
                                    findings databases
  evidence [options] <folder>       Write one folder of findings, SARIF, SBOM and fix branches, with
                                    a README that says what it does and does not show
  export-fixes [options]            Report what happened to the fixes 0 proposed, per repository:
                                    counts, pull requests, checks, cost and, on request, merged or
                                    closed
  report-draft [options] <finding>  Write a draft early warning, notification or final report about
                                    one finding (Markdown; nothing is sent)
  reproduce [options] <id>          Experimental: run a finding's proposed steps against a local
                                    copy of the app in a container with the network off, and record
                                    the result
  context                           Work with the business context file that orders findings
  help [command]                    display help for command

### 0security scan
Usage: 0security scan [options] [target]

Scan a folder or git repository for security bugs; prints the findings as a report

                               are kept (default: "5")
  --format <format>            Report format: json, md, sarif, html, pdf (default: "md")
  -o, --output <file>          Write the report to a file instead of stdout
  --fail-on <severity>         Exit 1 when a finding is at or above this severity (critical, high,
                               medium, low, info)
  --passes <n>                 Scan this many times and merge the findings (a scan misses some
                               issues that another run finds); the budget is split between them, up
                               to 5 (default: "1")
  --diff <ref>                 Review only the files that differ from this git ref (for example
                               origin/main), and what they connect to; an empty diff scans nothing
  --prepass <mode>             auto runs the pattern scanners first when they are installed and
                               gives their hits to the scan as leads; off skips them (default:
                               "auto")
  --scanner <id>               Scanner for the pre-pass (foxguard, semgrep, opengrep, gitleaks,
                               trivy, osv-scanner, checkov); nuclei is only for --target-url; repeat
                               or separate with commas to use several (default: foxguard). gitleaks,
                               trivy and osv-scanner must be installed; secret values are redacted
  --target-url <url>           With --scanner nuclei: test this running app with Nuclei, which you
                               installed. Needs --scope-file or --acknowledge-host. 0 sends no
                               request itself; link-local and cloud metadata addresses are always
                               refused
  --scope-file <file>          With --target-url: a file listing the hosts you may test, one host or
                               host:port per line
  --acknowledge-host <host>    With --target-url: type the exact host being tested. A public host is
                               refused without it
  --rate-limit <n>             With --target-url: Nuclei requests per second (1 to 150) (default:
                               "10")
  --templates <path>           With --target-url: a Nuclei template file or folder to run instead of
                               the templates Nuclei has installed. 0 never downloads templates
  --rules <file-or-folder>     Semgrep or OpenGrep rules for the pre-pass (a file or a folder);
                               repeat for several. Replaces the default rules and needs --scanner
                               semgrep or opengrep. Rules are never read from the scanned folder
                               unless you name them
  --business-context <file>    Operator-owned JSON tags and notes for investigation and work
                               ordering; keeps technical severity unchanged
  --repository <name>          Repository name the business context rules are matched against
                               (default: the git remote of the scanned folder)
  --context <file>             Give the scan this file (a threat model, notes on who may do what) as
                               lower-priority background; repeat for several. It can steer what the
                               scan weighs but cannot change how it works
  --policy <file-or-folder>    Check the code against these Markdown policies (a file or a folder of
                               .md files) and report pass or fail for each; repeat for several. Runs
                               the policy-check skill
  --org-policy <folder>        An organisation's policy folder: evaluated first, and wins when a
                               --policy says otherwise or uses the same id; repeat for several
  --scope <file>               Read the declared scope from the '## Scope' section of this Markdown
                               file (usually SECURITY.md). Findings that match a vector it lists as
                               out of scope are labelled, listed apart and left out of the counts,
                               --fail-on and the exit code; none are removed. In CI pass the base
                               branch's copy
  --repo-scope                 Read SECURITY.md from the scanned folder as the declared scope. Off
                               by default: a change under review can edit that file; in CI pass the
                               base branch's copy with --scope instead
  --scope-sarif <mode>         With --scope: label (default) writes the scope as result properties;
                               suppress also marks out-of-scope results suppressed, which GitHub
                               code scanning then dismisses (default: "label")
  --repo-context               Also read .0/threat-model.md from the scanned folder as context. Off
                               by default: a change under review can edit that file; in CI pass the
                               base branch's copy with --context instead
  --repo-ignores               Also let the pre-pass scanners read their configuration and ignore
                               files from the scanned folder (.foxguard.yml, .semgrepignore,
                               .gitleaks.toml, .gitleaksignore, .trivyignore, osv-scanner.toml,
                               .checkov.yaml). Off by default: a change under review can use them to
                               hide findings. Inline suppressions such as nosemgrep always apply
  --evaluation-sheet <folder>  After the scan, write a folder for judging the findings by hand:
                               review.csv with blank true positive, false positive, unsure and notes
                               columns, the findings with verdict, fix explanation and
                               business-context rank, the cost, time, model, scanner versions and
                               coverage, the exact command and CLI version, and a README that says
                               it is not an accuracy result. Refuses a non-empty folder
  --overwrite-sheet            With --evaluation-sheet: replace the sheet files in a folder that
                               already has files (other files are left alone)
  --poc-image <image>          Run the proof of concept of each high or critical finding in this
                               container image, network off, and label the finding script-matched,
                               script-unmatched or static-only. Must be pinned by digest
                               (name@sha256:...). Default: the ZERO_POC_IMAGE variable or `0security
                               config set executedPocImage`; otherwise off. Needs Docker or podman
  --skill <id>                 Skill that holds the scan method (default: "scan")
  --model <model>              Model for the scan thread (default: gpt-6-luna; ZERO_MODEL or a
                               pinned provider's default when set)
  --provider <id>              Explicit model provider for this scan (use with --model)
  --reasoning <effort>         Reasoning effort for a model that supports it
  --batches <mode>             auto reviews a large folder in batches, one thread per group of entry
                               points, and records what each batch covered; on always does; off
                               keeps one thread (default: "auto")
  --codeowners <file>          Group batches by an operator-provided CODEOWNERS file as well as
                               build module; reads no ownership file automatically and never skips
                               unowned code
  --batch-size <n>             Entry points one batch reviews (1 to 50); a folder with more than
                               this many is split under --batches auto (default: "8")
  --retries <n>                Run a batch again when it fails for a reason that may pass: a dropped
                               connection, a provider timeout, rate limit or server error (0 to 5; 0
                               turns it off). A thread that is not a batch is asked once to
                               continue. The cost of every attempt counts against --budget (default:
                               "2")
  --coverage-rounds <n>        After a thread ends, send it a follow-up that names the source files
                               it never opened, up to this many times (0 to 5; 0 turns it off). Each
                               round counts against --budget (default: "1")
  --batch-timeout <seconds>    Longest one batch may run before it is cancelled and left pending
                               (the scan goes on with the next batch); --timeout still limits the
                               whole scan (default: "900")
  --concurrency <n>            Batches that run at the same time (1 to 8; ZERO_SCAN_MAX_CONCURRENCY
                               allows up to 16). With --target-url: Nuclei templates that run at
                               once (1 to 25, default 5) (default: "1")
  --resume <scan>              Continue the units an earlier batched scan of this folder did not
                               reach (a scan id from its report, or latest); refuses when the git
                               HEAD changed unless --force
  --force                      With --resume: continue even though the folder's git HEAD changed
  --coverage [scan]            Print the coverage ledger of a batched scan of this folder (the
                               latest, or the id given) and exit; --format json for JSON
  --allow-partial              Exit by the findings alone (0, or 1 with --fail-on) when the scan
                               stops before it reviews everything; the report still says it is
                               partial
  --plan                       List the entry points, the batches and a rough cost range for the
                               folder, then exit; calls no model and writes nothing
  --tiers <file>               An operator's tier map (YAML or JSON) that sets the budget, batches
                               and skill for this repository, or skips it. Default:
                               scan-tiers.yaml|yml|json in the 0 state folder. Never read from the
                               scanned folder on its own; in CI read it from the base branch
  --fail-on-skip               Exit 1 when the tier map skips this scan (default: exit 0, with the
                               skip stated in the report)
  --known <sarif>              SARIF from other tools: the scan is told what is already known and
                               looks for what they missed; findings are labelled new or
                               already-known (confirmedIndependently when the scan analysed it
                               itself). Repeat for several
  --only-new                   With --known: leave findings that match a known item out of the
                               report
  --timeout <seconds>          Maximum seconds for the whole scan; what it reviewed so far is
                               reported as partial (default: "3600")
  --engine-url <url>           Attach directly to a running trusted engine
  --engine-token-env <name>    Environment variable holding the attached engine token
  --computer <id>              Use a registered remote computer
  --computers-config <path>    Operator computer connection registry JSON file
  --db-path <path>             Control database of the local engine to attach to
  -h, --help                   display help for command

  --port <port>                 Port to bind; 0 chooses a free loopback port (default: "48123")
  --host <host>                 Loopback host to bind (127.0.0.0/8 or ::1) (default: "127.0.0.1")
  --asset-dir <path>            Path to the built web app
  --dev-url <url>               Loopback Vite server for authenticated frontend hot reload
  --team-config <path>          Enable workspace accounts, roles, and shared conversation controls
  --engine-token-env <name>     Environment variable holding the engine bearer credential (32–4096
                                characters)
  --engine-workspace <path>     Engine-owned authorized workspace for persistent workflow calls
  --engine-allow-apply          Admit explicitly approved patch application in persistent workflow
                                calls
  --engine-time-cap <ms>        Server workflow deadline ceiling (default 600000 ms)
  --engine-cost-cap <usd>       Server workflow estimated cost ceiling (default $5)
  --server-mode                 Serve the console to a network behind a TLS proxy: requires sign-in,
                                an allowed-host list and a single node (off by default)
  --allowed-host <host...>      Server mode: accepted Host header names (default: only the bind
                                host); also ZERO_ALLOWED_HOSTS
  --trusted-proxy <cidr...>     Server mode: proxy addresses or CIDRs whose X-Forwarded-* headers
                                are trusted; also ZERO_TRUSTED_PROXY
  --public-url <url>            Server mode: the public https URL of this console (sign-in cookies,
                                single sign-on); also ZERO_PUBLIC_URL
  --access-token-env <name>     Server mode: environment variable holding the access token (32+
                                characters); default ZERO_ACCESS_TOKEN, else one is generated
  --shutdown-timeout <seconds>  Server mode: seconds to finish in-flight requests on SIGTERM
                                (default 20)
  --ready-json                  Emit the bound console URL as machine-readable JSON
  --no-open                     Do not auto-open a browser
  --headless                    Serve the API only: no browser, and no web app files needed (use
                                with `0security threads`)
  --engines-config <path>       Trusted engine connection registry JSON (default ~/.0/engines.json)
  -h, --help                    display help for command
